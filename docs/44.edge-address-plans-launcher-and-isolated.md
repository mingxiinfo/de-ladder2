# 44. 边缘隧道的两套地址：默认沿用 Launcher 的 10.88 编号，100.127 留作可切换的一套

日期：2026-11-22。状态：分两部分。

2026-11-22 第十九、二十轮：Launcher 的代码把 `10.88.88.88` 当成 Internal 的角色地址，用户选了 A（`docs/48`）。第 1 条地址表里"s1 的边缘地址 `10.88.88.88`"已被取代：launcher 方案把 `.88` 和 `.1` 一样保留，s1（internal01）以后加进边缘网用 `.87`；s2 的 `.89` 不变。tunnel-cli 的改动要发下一个版本。

**真机**：internal02 → domestic02 的隧道已经通了。这是用户用 2.1.17 在真机上跑的，用的还是 2.1.17 的 `100.127.202.0/24`。2026-11-22 稍后，用户说 domestic02 `10.88.0.2` ↔ internal02 `10.88.88.89` 也通了，就是本篇的 launcher 方案（npm 上最新是 2.1.19）；"还没做的"里"launcher 方案没在真机上跑过"一句因此不再成立（`docs/45`）。

**本篇的改动**：写在 L1 仓库的 tunnel-cli，没有提交，没发 npm 包，要发下一个版本才有。本机实测过：
- 一个 privileged 容器里放 internal02 和两个 domestic 网络命名空间，WireGuard 用真内核；
- internal02 上放了一张替身的 `mx-internal-svc`（`10.88.88.89` 加 `10.88.0.0/16` 的路由），模拟以后 s2 跑 Launcher 复刻的样子；
- tunnel-cli 的测试共 169 项：166 项通过，3 项跳过，0 项失败，其中 edge 37 项。

本篇取代 `docs/43` 第 3 条的地址表（默认改成 10.88），`docs/43` 其余结论不变：
- 只走 Domestic → Internal；
- nginx 分后端，DNS 分 Domestic；
- s1 先不加。

用户 2026-11-22 的说法：
- `100.127` 开头的是以前包里（tunnel-cli 隧道）的策略；
- 要保持以前的使用习惯：Internal 是 `10.88.88.88`，Domestic 是 `10.88.0.1`；
- 加了机器，Internal 能不能从 `10.88.88.89` 往上递增，Domestic 要不要也递增；
- 原来那套 `100.127` 保留成可切换的，它不容易冲突，以后给别的机器集群部署时可以先用它。

同一次，用户贴的真机输出：

- 随后 `edge link check domestic02` 两端都有握手，ping 都通。

## 结论

1. **默认用 launcher 方案，和 Launcher 用同一套编号**：

   | 机器 | Launcher 网络（`mx-domestic` / `mx-internal-svc`） | 边缘隧道 |
   |---|---|---|
   | 现在那台 Domestic（domestic-main） | `10.88.0.1` | 不推（`docs/37`），`10.88.0.1` 保留给它 |
   | domestic02 | — | `10.88.0.2` |
   | domestic03 | — | `10.88.0.3` |
   | s1（internal01） | `10.88.88.88` | `10.88.88.88`（暂不加） |
   | s2（internal02） | `10.88.88.89`（Launcher 复刻，`docs/36`） | `10.88.88.89` |

   - 同一台机器在两张网里是同一个地址，所以"Internal 是 10.88.88.x、Domestic 是 10.88.0.x"的习惯不变。
   - Internal 从 `.88` 往上递增，规则是 `.87+N`。
   - **Domestic 也要递增**：每台 Domestic 必须有自己的地址，规则是 `10.88.0.N`。原因：
     - Internal 这边每台 Domestic 一个对端，WireGuard 的 AllowedIPs 和路由都按地址区分；
     - nginx 日志、访问控制也要靠地址分清是哪台 Domestic。
   - `10.88.0.1` 一直归 Launcher 的中继。
2. **能和 Launcher 的 10.88 共存，靠"只路由 `/32`"**。Launcher 自己在 10.88 里用的地址都留着（出处见下）：
   - `10.88.0.1`：中继。Internal 网关只认这一个地址（`45-internal-gateway.yaml` 的 `remote_ip 10.88.0.1`），`10.88.0.2` 不会被当成 Domestic 转来的请求；
   - `10.88.88.88`：控制面和 DNS；
   - `10.88.100.0/24`：产品的 service VIP。

   边缘隧道不碰这些地址：
   - Domestic 上的中继只占自己的 `/32`（比如 `10.88.0.2/32`），只为每个 Internal 的 `/32` 加路由，不再占整段。
   - Internal 上只为每台 Domestic 的 `/32` 加路由，比 Launcher 的 `10.88.0.0/16` 更具体，只把那一个地址引到边缘隧道。`10.88.0.1` 和其他 10.88 地址照旧走 `mx-internal-svc`。
   - 出处：`mx-launcher/server/src/store/domain.ts`、`site-slot-artifact-materializer.mjs`、`deploy/k8s/internal-shadow/45-internal-gateway.yaml`，源码里写着。
3. **工具会拒绝的地址**：
   - `10.88.0.1` 和 `10.88.100.0/24`；
   - 本机已经有别的网卡在用的地址：精确的 `/32` 路由，或者本机地址。

   更宽的路由（Launcher 的 `/16`）不算冲突，`init` 时会列出来，说明 `/32` 比它更具体。
4. **isolated 方案（`100.127.200.0/24`）保留，可以切换**：
   - 编号规则一样：Domestic `.N`，Internal `.87+N`；
   - 它和 Launcher 用的地址没有交集，适合以后给别的机器、集群用；
   - 一台推送机上两套方案可以同时用，每台 Domestic 一条隧道，各选各的。
5. **怎么选方案**：
   - `edge link init <机器> --plan launcher|isolated`；
   - `edge setup` 在隧道那一步先问"Address plan"，默认 launcher；这台推送机已有 isolated 的隧道时，默认 isolated；
   - `--plan` 给了、`--ip` 没给时，按规则自动填，不在终端也能用；
   - 方案写进 `link.env` 的 `LINK_PLAN`，`edge link show` 看得到。
6. **2.1.17 建的那条 `100.127.202.0/24` 继续能用**：新版本照样认它。想换到 10.88，用 `edge link init domestic02 --replace --plan launcher`，或者 `edge setup` 里对"Use this link?"答 n，再推一次、`link up` 一次。旧文件挪到 `replaced/`，不删。
7. **换成 10.88 之后，s2 要跟着改两处**（`docs/35` 阶段 host-nginx 那张端口表要补）：
   - host-nginx 要在 `10.88.88.89` 上监听；
   - ufw 要放行来自 `10.88.0.2`（以及之后每台 Domestic）的 80。

   Domestic 上 nginx 的后端写 `http://10.88.88.89:80`。
