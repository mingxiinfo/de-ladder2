# 13. 架构图：怎么画、放哪、怎么用来讲

日期：2026-11-16；2026-11-17 更新。状态：文档里的 Mermaid 图已写（没有用渲染器验证过）；Archify 图册已生成 4 张，全部通过 Archify 的 showcase 校验，其中 02 和 04 用无头浏览器截图目视检查过。

## 两种图，两个用途

| | Mermaid | Archify 图册 |
|---|---|---|
| 写在哪 | 文档正文里的 `mermaid` 代码块 | `docs/atlas/*.json`（源）生成 `docs/atlas/*.html` |
| 给谁看 | 读文档的人。GitHub、VS Code、多数 Markdown 阅读器直接渲染 | 宣讲、发给同事。单个 HTML 文件，自带主题、缩放、路径查看、导出 |
| 维护成本 | 低，改文字就行 | 每张图要手工定位置，改完要重新生成和检查 |
| 依赖 | 无 | 需要 archify 命令行（Node），已安装 |

规则：**每篇文档至少一张 Mermaid 图**，它是随文档一起更新的那份。图册只挑最值得讲的几张做，内容以对应文档为准。

选 Archify 是因为 L1 已经在用：`mx-insight-hub/docs/architecture/atlas/` 里的 Hub 技术交流图册就是它生成的（版本 2.17.0-dev.1），团队看过也认可这种形式。

## 生成图册

Archify 的仓库是 `github.com/tt-a1i/archify`，2026-11-17 克隆到 `~/.local/share/archify`（提交 `a7ed6fd`，浅克隆约 140M）。命令行入口在它的 `archify/bin/archify.mjs`，`manage.sh` 默认去这个位置找，装在别处就设置 `ARCHIFY_BIN`。

```bash
git clone --depth 1 https://github.com/tt-a1i/archify ~/.local/share/archify   # 换机器时
./scripts/manage.sh diagrams            # 生成 docs/atlas 下所有源文件对应的 html
./scripts/manage.sh diagrams 02-target  # 只生成一张
```

源文件命名是 `<编号>-<名>.<类型>.json`。写新图时的几条经验：

- `meta.output` 是必填的。
- architecture 类型用 `layout.mode: grid` 加每个组件的 `row` / `col`，比手写坐标省事。
- 边界框（`boundaries`）按成员的外接矩形画，框里不能有非成员。把同一个框的成员排成紧凑的一块。
- dataflow 类型每条连线必须有非空的 `label`；多条线汇入同一个节点时，用 `fromSide` / `toSide` 让它们从不同的边进，标签才不会压线。
- 先 `archify validate <类型> <文件> --quality showcase` 看报错，它会给出具体的修改建议。

工具校验通过只说明布局没问题，不说明内容对。每张图生成后要对着来源文档看一遍。

## 画图的约定

- 图里的每个框都能在 `inventory/` 或某篇文档里找到。不画"以后可能有"的东西，除非框上写明"计划"。
- 没实测的连接用虚线，或者在图的标题里写明。
- 一张图回答一个问题。超过 15 个框就拆。
- 机器、命名空间、端口用 `inventory/` 里的名字，不另起别名。
- 图里不出现密码、token、公网地址。
