# 11. 迁移路线与验收

日期：2026-11-16。状态：计划，一步都还没执行。 **P1 改用 kubeadm（16）；P3 的 mx-static 不再是必经步骤（20），备份提前到 P1 之后立刻做（19）；P8 的见证机取消（16）。**

## 原则

1. **s1 上的 Launcher 栈排最后。** 在它之前的每一步都不改 s1 上任何监听端口、地址、iptables 规则。
2. 一次迁一个服务，一次切一个域名。切换点是宿主机 Nginx 的一行 upstream，切回去也是一行。
3. 只复制不删除。旧实例停掉但保留，业务验收后由人显式清理。
4. 每一步做完都跑一遍 H2I 验收（见下）。哪怕这一步看起来和 H2I 无关。
5. 一步没验收完，不开始下一步。

## H2I 验收（每一步之后都做）

| 项 | 怎么验 |
|---|---|
| 已有账号登录 MX-H2I | 用一个已有的真实账号在已安装的客户端上登录 |
| 已有联网 | 登录后访问一个内网服务和一个外网地址 |
| Luopan 桌面端 | 启动、登录、打开首页 |
| SSO | Hub、DataPort、Pay 各登录一次 |
| 支付 | Pay 首页能打开；对账页面数字和迁移前一致 |

健康检查接口返回 200 不能代替这张表。L1 的文档反复强调过这一点。

## 阶段和步骤

  P0[P0 备好 s2<br/>系统 · NAS · 隧道] --> P1[P1 建集群<br/>k3s · 网关 · CNPG]
  P1 --> P2[P2 样板服务<br/>全链路打通 + 压测基线]
  P2 --> P3[P3 基础服务<br/>备份 · 镜像仓库 · mx-static]
  P3 --> P4[P4 数据面<br/>pg-common · ES · HanLP]
  P4 --> P5[P5 业务<br/>Hub · DataPort · Rig]

| 阶段 | 做什么 | 完成的标志 | 碰 s1 吗 |
|---|---|---|---|
| P0 | s2 装系统、分盘（`docs/07`）、挂 NAS、配 WireGuard 和 OpenVPN 地址、装宿主机 Nginx | `./scripts/manage.sh doctor` 在 s2 上全绿 | 不碰 |
| P1 | 装 k3s、网关、CloudNativePG | Gateway `main` 状态 Programmed | 不碰 |
| P2 | 用 `templates/project` 部署样板服务；Domestic 加一个测试域名指向 s2 | 公网能打开样板页面；拿到 `docs/09` 的基线数字 | 不碰。Domestic 只**新增**一个 server 块 |
| P3 | 对象存储和备份流水线；恢复演练跑通一次；内网镜像仓库；mx-static 上线 | 一次完整的"备份 → 恢复到临时实例 → 核对"成功 | 不碰 |
| P4 | 在 s2 建 `pg-common`、ES、Redis、HanLP；从 s1 复制 Hub 和 DataPort 的库（这时只是副本，不切流量）；在 L2 重建搜索索引 | 副本数据核对一致；索引建完 | 只读：从 s1 的库读数据 |
| P5 | 逐个切：Rig（风险最小，先拿它练手）→ DataPort → Hub。每个都是：停写、追平、切连接、切域名、验收 | 每个项目各自验收通过；s1 上对应的工作负载缩到 0 | 把 s1 上该项目缩到 0；改 s1 宿主机 Nginx 里该域名的上游（或由 Domestic 直接指向 s2） |
| P6 | Pay：单独窗口，迁移前后对账 | 对账一致；Hub 和 DataPort 的支付调用正常 | 同上 |
| P7 | Launcher、身份、Caddy。**单独写设计文档再做**，这里不展开 | H2I 验收全过，并观察一段时间 | 是，这是唯一大动 s1 的阶段 |
| P8 | s1 卸载 kubeadm，加入 L2；见证机加入；数据库加从库 | 关掉任意一台，无状态服务不中断 | 是 |

P5 之后 s1 上剩下：Launcher 栈、Night-All、po-*、宿主机 PG、GPU 服务。这时 s1 的内存和磁盘占用应该明显下降，达到"两台分担"的目标。**P7 和 P8 可以长期不做**，系统停在 P6 是一个稳定状态：s1 管身份和网络，s2 管数据和业务。

## 迁移期间跨集群的依赖

L2 的服务在 Launcher 迁过来之前要回 s1 调这些东西：

| 依赖 | s1 上的位置 | L2 里怎么访问 |
|---|---|---|
| SSO：授权页、token、内省 | Launcher（Caddy 8008 / 18090、公网身份 18444） | 浏览器走公网域名不变；服务端内省走指向 s1 LAN 地址的集群内 Service，结果要缓存 |
| Night-All 的接口 | 宿主机进程 | 指向 s1 的集群内 Service |
| 宿主机 PG 5432（源数据） | s1 的 `127.0.0.1` | 它现在只听回环。要让 s2 访问，得让它多监听 LAN 地址并限定来源。这是对 s1 的改动，P4 之前单独评估，或者让依赖它的组件暂时留在 s1 |
| Embedding（如果重开） | s1 的 `127.0.0.1:18210` | 同上的问题。倾向于重开时直接开在 s2 |

最后两行是迁 Hub 的真正难点：Hub 依赖 s1 上只听回环的服务。P4 开始前要先确认 Hub 的哪些工作负载用到宿主机 PG。

## 回退

| 步骤 | 怎么退 |
|---|---|
| P0 到 P4 | 没切流量，停掉 s2 上的东西即可 |
| P5、P6 的每一次切换 | 域名的上游指回 s1；s1 上的工作负载从 0 扩回原副本数。**切换后在 L2 产生的新数据要决定怎么处理**：窗口内发现问题就丢弃并回退；过了窗口就只能往前修 |
| P7 | 在它自己的设计文档里写 |

每次切换前写下回退窗口多长（建议 30 分钟）和谁有权决定回退。

## 现在可以开始的事

不依赖任何待确认信息、也不碰 s1 的：

1. 确认 s2 的硬件和地址，填进 `inventory/hosts.yaml`。
2. P0：s2 的系统、分盘、NAS 挂载。
3. P1：装 k3s 和平台组件，把 `infra/` 里的清单第一次放到真实集群上跑，修掉跑不通的地方。
