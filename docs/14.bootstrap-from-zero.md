# 14. 从 0 到 1：一台新服务器怎么变成集群节点

日期：2026-11-16。状态：**草稿，没有在任何机器上执行过。** 第一次在 s2 上做的时候逐步核对，把实际输出和改动补回这篇。 **第 6 节（k3s）已被 16 取代，见本文末尾的修订。** 2026-11-19：第 1–9 节在 s2 上的做法已被 `docs/35` 取代，按那里的 14 个阶段用 `node prepare` / `node verify` 做；第 7 节"转到 `127.0.0.1:30080`"改成转到本机 LAN 地址。

这篇是知识库的起点。以后每个环境（s2、见证机、云服务器）实际部署一次，就在这里补一节或新增一篇。

## 0. 开始之前

填好 `inventory/hosts.yaml` 里这台机器的：主机名、LAN 地址、WireGuard 地址、磁盘、GPU。标着"待确认"的不要跳过。

检查网段冲突（`docs/08` 的表）：

```bash
ip -br addr
ip route
```

## 1. 系统

- 主机名唯一，写进 `/etc/hosts`。
- 时间同步开着（etcd 和证书都依赖时间）。
- 关 swap，或确认 k3s 的版本支持带 swap 运行。
- 内核参数：`vm.max_map_count=262144`（Elasticsearch 需要；L1 是在 mx-common 的 `ensure` 里设的）。
- 防火墙：按 `docs/08` 的原则，先只对 LAN 开放。

## 2. 磁盘

按 `docs/07` 的目录规划。数据盘用 xfs、`noatime` 挂到 `/data`，用 UUID 写 fstab：

```bash
lsblk -f
mkdir -p /data/{k3s,cache/static,models,tmp}
```

**不用 bind 挂载搬目录。** s1 的 fstab 里有七行 bind 挂载（见 `inventory/hosts.yaml`），那是事后迁移留下的。新机器在安装时就把目录指到对的盘上。

## 3. NAS

加和 s1 同样的 fstab 行（`docs/07`），然后：

```bash
mkdir -p /mnt/nas
mount /mnt/nas
df -hT /mnt/nas
ls /mnt/nas            # 能看到 infra、delta 等目录才算挂对了
```

让 k3s 在 NAS 挂好之后再启动，新建 `/etc/systemd/system/k3s.service.d/10-requires-nas.conf`：

```ini
[Unit]
RequiresMountsFor=/mnt/nas
```

（s1 上对应的是 `/etc/systemd/system/docker.service.d/20-requires-nas.conf`。）

## 4. 隧道

- WireGuard：照 s1 的配置加一个 peer，地址用登记的那个。在 Domestic 上加对应的 peer。**不改 s1 的 WireGuard 配置。**
- OpenVPN mesh（运维用）：按 `docs/08` 的命令 create 加 enroll。

验证：从 Domestic `ping` 新机器的 WireGuard 地址。

## 5. 宿主机 Nginx

装系统自带的 Nginx，只监听 80。配置来自部署仓的 `compass/deploy/internal-nginx/`。先只放一个健康检查：

```nginx
server {
    listen 80 default_server;
    location = /gateway-health { return 200 "ok\n"; }
    location / { return 404; }
}
```

## 6. k3s

```bash
# 版本来自 infra/k8s/versions.env
install -d -m 0755 /etc/rancher/k3s
cp infra/k8s/cluster/k3s-server.yaml /etc/rancher/k3s/config.yaml
vi /etc/rancher/k3s/config.yaml        # 改 node-name、node-ip、tls-san

# 国内网络用 k3s 的国内安装脚本和镜像（地址在 cc-studio 的 infra/k8s/cluster/README.md 里核对过，这里没重新核对）
curl -sfL https://rancher-mirror.rancher.cn/k3s/k3s-install.sh | \
  INSTALL_K3S_MIRROR=cn INSTALL_K3S_VERSION="$K3S_VERSION" sh -s - server

kubectl get nodes
```

下载并执行安装脚本之前先看一遍它的内容。离线安装的办法（先下二进制和镜像包）以后补。

装完把 kubeconfig 拷到运维机，context 改名为 `ladder2`，不要叫 `default`：

```bash
kubectl config rename-context default ladder2
```

## 7. 平台组件

```bash
./scripts/manage.sh k8s platform gateway  --context ladder2
./scripts/manage.sh k8s platform postgres --context ladder2
./scripts/manage.sh k8s status --context ladder2
```

然后把宿主机 Nginx 的某个测试域名转到 `127.0.0.1:30080`，验证网关能通。

## 8. 样板服务和全链路

按 `docs/10` 用 `templates/project` 部署一个样板服务，再在 Domestic 加测试域名。从公网打开页面，检查应用日志里的客户端地址是不是真实的公网地址（验证 `docs/05` 的信任链）。

## 9. 备份（做完这步才算能用）

- etcd 快照同步到 NAS 和 s1。
- 数据库备份到对象存储，恢复演练跑通一次（`docs/06`）。
- k3s 的 token 和 `/var/lib/rancher/k3s/server/tls` 加密备份。没有它们，快照恢复不出来。

## 加入第二、第三台 server（阶段 B）

```bash
install -d -m 0755 /etc/rancher/k3s
cp infra/k8s/cluster/k3s-server-join.yaml /etc/rancher/k3s/config.yaml
# 填 server 地址；token 放到 /etc/rancher/k3s/cluster-token，权限 0600
```

server 总数保持奇数。见证机在配置里加污点，不跑业务：

```yaml
node-taint:
  - "ladder2/witness=true:NoSchedule"
```

## 程序构建

各项目的构建方法在各自仓库。平台这一层只约定：

| 事项 | 约定 |
|---|---|
| 在哪构建 | s2（阶段 A）；构建临时目录 `TMPDIR=/data/tmp` |
| 出网代理 | 只在构建时用，通过 `PROXY` 传给子项目（L1 的约定，`127.0.0.1:7788`）。不改 Docker daemon 的全局代理，不进运行环境 |
| 构建缓存 | buildx 的缓存要设上限并定期清（L1 用的是 2GB / 24 小时），否则会吃满数据盘 |
| 产物 | 镜像推到内网镜像仓库（建好之前：导入本机 k3s） |

## 修订（2026-11-17）：第 6 节改用 kubeadm

依据 `docs/16`。没有实测。

```bash
# 1. 各节点 /etc/hosts
echo "192.168.1.4 k8s-api.ladder2.internal" >> /etc/hosts

# 2. containerd、kubeadm、kubelet、kubectl：版本与 s1 一致（v1.36）。Ubuntu 用 apt，从 pkgs.k8s.io 的 v1.36 仓库装

# 3. 建集群

vi /root/kubeadm-init.yaml            # 改主机名、补丁版本、WireGuard 地址
kubeadm init --config /root/kubeadm-init.yaml --upload-certs

# 4. flannel，Pod 网段改成 versions.env 的 POD_CIDR（2026-11-22 起是 192.168.224.0/20，和 s1 一样，docs/41；install.sh 会改）
```
